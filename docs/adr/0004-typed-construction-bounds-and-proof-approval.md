# Pure validated construction, finite defaults and scoped proof govern public use

<a id="adr-0004"></a>

Configuration retains settings without effects; build reports every problem and makes the admitted Agent or Runtime. Callers select ids before start, retain native final-answer types and handle structured failure classifications. Source-defined invalid constants may panic at their stated constructor; values from runtime configuration need typed validation before resource allocation.

Finite defaults include eight agent model attempts, four tool bodies, a 600-second model call, 60-second tool body, 1 MiB retained result, five-second policy/command waits, seven-day approvals and graph waits, 100 graph activations and 25-second invocation/store drain. Infinity is explicit where supported. Token budgets are opt-in because absent provider usage cannot truthfully mean zero. These bounds govern different resources; they do not imply global service capacity or a whole-run deadline.

Typed answer codecs replace application parsing of a string convention and remain checked after tool use. One corrective answer turn is default, funded by remaining model/token bounds. Caller-supplied RunId permits retried starts to inspect an existing identity. Explicit errors distinguish refused command, incompatibility, transient conflict and unknown store operation.

A Reviewer value alone cannot establish authenticated authority across packages. The selected approver port returns an opaque scoped proof from the exact configured verifier instance. Verifier, requirement and proof age are checked for every answer; configured approval expiry is retained in run records. Proofs need not be single-use because the durable answer is once-only. A Warden-specific proof type or dependency was rejected; verifier setup is shared at application boot.
