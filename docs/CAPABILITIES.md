# Fabric capability inventory

This inventory maps each BeamWeaver capability surveyed in
[research/beamweaver-oracle.md](research/beamweaver-oracle.md) (§2) to its
Fabric disposition. The oracle pin and fixture rules are in
[ORACLE.md](ORACLE.md); the slice plan and public API are in [PLAN.md](PLAN.md).

## Dispositions

- **Fabric** — Fabric implements the behaviour itself.
- **Integration** — another gleam-dream package supplies it; Fabric consumes
  its public contract, possibly through an optional adapter.
- **Backlog** — retained requirement, not yet built. Unfinished work, not an
  exclusion.
- **Excluded** — a deliberate, documented non-goal.

Validation methods: **unit** (pure controller tests), **runtime** (OTP tests with
real processes and barriers), **stub** (llm_wire against a local HTTP/SSE stub),
**consumer** (`consumers/app`, public imports only), **oracle** (executed
BeamWeaver differential fixture), **inspired** (original Fabric test motivated
by BeamWeaver source or tests; not a comparison).

## Exclusions versus unfinished work

- **Excluded** (not planned): retrieval, vector stores and document loading;
  multi-node distributed coordination; a LangGraph-compatible graph API
  (breakpoints, time travel, channels, `Send`); async sub-agents over the remote
  Agent Protocol; a general middleware chain.
- **Unfinished** (backlog, ordered by slice in PLAN.md): budgets shared
  across a sub-agent family (slice 2b backlog),
  approval expiry and edit/respond answers (slice 2a backlog),
  streaming (slice 3), structured output (slice 3), elapsed-time budget
  (slice 3), database store adapters (slice 3), compaction (v2).
